--------------------------------------------------------------------------------

A) GEÇMİŞ VERİ KATMANI  (kaza-namazi-takip-gecmis-v1)
   Günlük kayıt formatı — her gün bir anahtar:
     "YYYY-MM-DD": {
       kaza:  { sabah: 3, ogle: 1, ikindi: 0, aksam: 2, yatsi: 0, vitir: 1 },
       bulk:  { sabah: 5000, ... },      // toplu ekleme ayrı işaretli
       kalan: { sabah: 120, ... },       // gün sonu kalan borç anlık görüntüsü
       toplamKaza: 7,
       toplamBulk: 5000,
       toplamKalan: 120
     }
   - Mevcut 'counts' bozulmadan korunur. İlk kurulumda geçmiş boş başlar.
   - Her sayaç değişimi (PrayerCard +1/-1/+5/-5, BulkAddModal, Undo)
     ilgili günün kaza/bulk kaydını günceller.
   - Kalan borç anlık görüntüsü her günün sonunda yazılır.
   - Grafikler 'kaza' + 'bulk' toplam olarak gösterir (K-15).

B) EKRAN YAPISI  — 3 sekmeli alt tab bar
     [ Takip ]  [ Özet ]  [ Ayarlar ]

3. BILDIRIM MIMARISI  (CEVAP: EVET, UYGULAMA KAPALIYKEN DE VERILEBILIR)
--------------------------------------------------------------------------------
 SORU: "Bildirimi veremiyor muyuz uygulama kapaliyken?"
 CEVAP: VERILEBILIR. Ama yontem degisir. Mobil web'de iki farkli sey vardir:

   (1) SAYFA ACIK / ARIK PLANDA (foreground)
       = Tarayici Notification API'si + setTimeout.
       Sunucu gerekmez. Bildirim aninda, uygulama ekrandayken calisir.
       TIKLANINCA: ilgili vakit kartina gidilir ve sayac tek dokunusla artirilir.

   (2) SAYFA KAPALI (background)  --> GERCEK PUSH GEREKIR
       = Web Push (VAPID) + bir sunucu.
       Telefona "abone ol" (subscribe) yapilir. Sunucu, vakit gelince
       push mesaji gonderir. Telefo interneti olsa da olmasa da (asagidaki
       not) teslim edilir.

   DIYANET ILE AYNI HESAP SUNUCUDA YAPILAMAZ
   Adhan hesabini sunucuda degil, KULLANICININ CIHAZINDA yapip vakit
   zamanlarini bir kere sunucuya kaydediyoruz. Sunucu sadece "bu saatte
   5 vakit bildirimi gonder" diye zamanlanmis is yapacak. Boylece
   sunucu ucuz ve guvenilir kalir, hesap hatalari olmaz.

   ------------------------------------------------------------------
   KATMAN 1 - KULLANICI AYARINDAN "NAMAZ VAKTI" TANI (5 vakit)
   ------------------------------------------------------------------
   Kullanici Ayarlar ekraninda secim yapar:
     [x] Sabah  [x] OgIe  [x] Ikindi  [x] Aksam  [x] Yatsi
   Secilen her vakit icin, o gunku vakit saati hesaplanir ve push
   aboneliği olusturulur (endpoint + keys sunucuda saklanir).
   Bildirim icerigi ornegin:
     "OgIe vakti 13:05"  /  "Yatsi vakti - 20 dk kaldi"
   Bildirime TIKLANINCA: uygulama acilir, ilgili vakit karti vurgulanir
   ve sayac tek dokunusla +1 yapilabilir.

   ------------------------------------------------------------------
   KATMAN 2 - NAFILE VAKIT BILDIRIMI
   ------------------------------------------------------------------
   Kullanici Ayarlar'da hangi nafileyi istedigini secir:
     [ ] Teheccud (gecenin son ucte biri)
     [ ] Kusluk / Duha (gunes dogusu + 50 dk)
     [ ] Evvabin (Aksam + 20 dk)
   (Yalnizca sahih nafile namazlar; Istikamet/Evsab secenek degildir.)
   Secilen nafile icin ayrica vakit hesaplanir ve bildirim planlanir.
   Ornek: "Teheccud vakti 02:41 - kaza namazin icin uygun saat".

   ------------------------------------------------------------------
   KATMAN 3 - SUNUCUSUZ / YEDEK YOL: .ics TAKVIM DOSYASI
   ------------------------------------------------------------------
   Istemci tarafinda uretilir, sunucu YOK, veri disari cikmaz.
   Kullanici "Takvime ekle" derse, o gunun 5 vakti + secili nafile
   icin bir .ics dosyasi (VALARM) indirilir.
   Telefonun kendi takvimi alarmi devralir -> uygulama kapali olsa bile
   telefonun kendi bildirimi gelir. iOS dahil HER YERDE calisir.
   Bu, Web Push'a gore daha guvenilir ama tek seferlik/gunluk yenileme gerekir.

   ------------------------------------------------------------------
   KATMAN 4 - WEB PUSH SUNUCUSU (Vercel serverless)
   ------------------------------------------------------------------
   - Vercel'de bir serverless function + VAPID anahtarlari.
   - Push endpoint'leri ve abonelik bilgisi bir depoda tutulur.
   - Zamanlanmis is: her gece yarisi ertesi gunun vakit saatleri hesaplanir
     ve push gonderilir. (Gundelik, uygulama hic acilmasa da)
   - Not: Vercel Hobby planinda cron isleri sinirli olabilir ->
     alternatif: harici bir cron (cron-job.org) GET istegi atar.

   ------------------------------------------------------------------
   GERCEKCI KISITLAMALAR (soz vermeden once bilinmeli)
   ------------------------------------------------------------------
   1. iOS'ta Web Push SADECE uygulama ana ekrana eklenmis PWA iken calisir.
      "Safari'de ac" halinde calismaz. Bu yuzden .ics yolu olmazsa olmaz.
   2. Bildirim izni ilk acilista istenir; reddedilirse geri alinamaz
      (tarayici ayarindan degistirilmeli). Kullanicidan "izin ver" diye
      isteyen bir onboarding ekrani gerekir.
   3. Periodic Background Sync sadece Chrome'da var, iOS'ta YOK.
   4. "Bildirim sayacini otomatik artir" -> supheli/kaza riski ->
      varsayilan KAPALI, kullanicinin acikca onaylamasi gerekir.
   5. Sunucu maliyeti: kullanici sayisi artarsa Vercel function + DB
      maliyeti devreye girer. Kucuk olculu uygulama icin bedava kalir.

   ------------------------------------------------------------------
   TAVSIYE (BENIM ONERIM)
   ------------------------------------------------------------------
   Faz 3'te: Katman 1 + Katman 2 (uygulama acikken aninda bildirim)

3B. "ARKA PLANDA IZIN + WIDGET GIBI CALISMA" — TEKNİK GERÇEK
--------------------------------------------------------------------------------
 SORU: "Açık kalması için arka planda izin istesek, arka planda çalıştırsak,
       bildirim sistemini widget gibi de yapabilir miyiz?"

 CEVAP: Widget gibi bir yapı web'de MÜMKÜN DEĞİL, ama hedefe en yakın
        çözüm şu: Push + Service Worker + Bildirim Etkileşimi.

 NEDEN WIDGET OLMAZ:
 - Ana ekran widget'ı OS/native bir bileşendir. Bir web sitesi/iş web
   uygulaması widget üretemez. (iOS 26'da "web app widget" diye bir şey
   YOK; WebKit'in kendi blogunda listelenen yeni web yetenekleri arasında
   widget desteği yer almıyor.)
 - PWA manifest'inde bir widget bildirimi yoktur. Bildirimlerin
   "ana ekranda sabitlenmiş kart" gibi davranması icin yapılabilecek sey:
   Bildirim actions (bildirime "Sabahı ekle" gibi buton koymak) + Badging
   (ikonun uzerine kalan borcu yazma).

 WEB'DE ARKA PLANDA CALISMANIN 3 YOLU (teknik olarak dogru siniflandirma):
   YOL A - Service Worker + Web Push (GERCEK ARKA PLAN)
     Telefo kapaliyken bile gelir. Sunucu (VAPID) gerektirir.
     iOS'ta SADECE ana ekrana eklenmis web app icin (iOS 16.4+).
     -> BIZIM ANA HEDEFIMIZ BU.
   YOL B - Declarative Web Push (iOS 18.4+ / macOS 15.5+)
     Service worker'a GEREK YOK. Sunucu, bildirimin icerigini HTTP
     basliginda hazir JSON olarak gonderir; tarayici gosterir.
     Daha az pil, daha cok gizlilik. Bizim icin avantaji: custom SW
     yazmaya gerek kalmaz -> mevcut vite-plugin-pwa yapisi bozulmaz.
     Dezavantaj: icerigi sunucu tarafinda hazirlamak gerekir (baska bir
     yandan zaten saatleri sunucuda kaydedecegiz, sorun degil).
   YOL C - Periodic Background Sync (SADECE CHROME/ANDROID)
     "widget gibi arka planda calis" fikrine en yakin sey. Service
     worker periyodik olarak uyanir. iOS'ta YOK. Guvenilirligi dusuk
     (tarayici belirledigi araliklar, batarya izleyebilir).
     -> Bizim icin opsiyonel, Chromium kullanicilar icin.

 "BILDIRIM IZNINU ARKA PLANDA ALMA" HAKKINDA:
   Bildirim izni SADECE kullanicinin dokunmasina (user gesture) bagli
   olarak istenebilir. Arka planda "kendiliğinden izin isteme" diye bir
   sey YOKTUR. Yani once kullanicinin Ayarlar'da "Namaz vakti
   bildirimlerini aç" butonuna basmasi gerekir (bizim tasarimimiz), sonra
   tarayici izin penceresini gosterir. Arka planda izinsiz bildirim
   gondermek mumkun degildir ve denemek de kullanici guvenini zedeler.
   -> Bu bir "kisit" degil, "dogru UX akisi"dir.

 SONUC / PLAN ETKIISI:
   Bildirim mimarisi şu sekilde netlestirildi:
     - Faz 3: Foreground bildirim + .ics (sunucusuz, aninda calisir)
     - Faz 4: Web Push (Yol A + Yol B birlikte: standart push + declarative
             push fallback). Sunucu tarafi Vercel serverless.
     - Bildirim etkileşimi: bildirimde butonlar ("Sabahı +1 ekle"),
       tiklayinca uygulama acilir ve ilgili vakit vurgulanir.
     - Badge: kalan borcu ana ekran ikonunda goster (Badging API,
       iOS 16.4+ Home Screen app'lerde calisir).
     - Widget: yapilamaz -> onun yerine "ana ekrana sabitlenmis hizli
       erisim sayfasi" (start_url ile /ozet ?veya koyu tema) + badge.
